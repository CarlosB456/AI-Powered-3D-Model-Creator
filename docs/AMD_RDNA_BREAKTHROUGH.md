# The AMD RDNA 2 (RX 6600 8GB) Breakthrough

A technical breakdown of how we achieved **~2 minute** state-of-the-art 3D generation on an **AMD Radeon RX 6600** (8GB GDDR6 VRAM) under Windows without Linux or native ROCm.

---

## 1. The Challenge

Modern state-of-the-art Image-to-3D pipelines such as **Hunyuan3D-2** rely on three massive sub-networks:
1. **DINOv2 Giant Vision Encoder**: 1.14 Billion parameters. Requires high-resolution feature maps ($1022 \times 1022$ pixels) producing $5,330$ spatial patch tokens.
2. **Hunyuan3D Diffusion Transformer (DiT)**: 560 Million parameters with multi-stream cross-attention and text/image guidance.
3. **ShapeVAE & Point Decoder**: 328 Million parameters, querying millions of 3D spatial points to compute signed distance / occupancy values.

When executed naively:
- Moving the full pipeline to GPU requires over **14 GB of VRAM**, instantly crashing on mid-range 8 GB cards (NVIDIA RTX 4060, AMD RX 6600, RX 7600).
- Falling back to CPU produces painful runtimes of **11 to 15 minutes** per generation.
- DirectML historically suffered from memory fragmentation and unsupported kernel crashes on large attention sequence lengths.

---

## 2. Key Technical Innovations

### Innovation A: Chunked Self-Attention for DINOv2

#### The Bottleneck:
In standard `transformers.models.dinov2.modeling_dinov2.Dinov2SelfAttention`, attention is calculated across all tokens simultaneously:
$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$
For $L = 5,330$ tokens across $H = 24$ attention heads, the attention score matrix $QK^T$ requires:
$$5,330 \times 5,330 \times 24 \times 2 \text{ bytes (FP16)} \approx 1,363,627,200 \text{ bytes (1.36 GB)}$$
DirectML cannot allocate a contiguous 1.36 GB temporary tensor on an 8 GB card alongside model weights, throwing a fatal DirectML `RuntimeError` / Out-Of-Memory exception.

#### The Solution:
We implemented a non-invasive monkey-patch that slices the query matrix $Q$ into sub-blocks of size $C = 512$:
```python
chunk_size = 512
context_chunks = []
for i in range(0, L, chunk_size):
    q_chunk = query_layer[:, :, i:i+chunk_size, :]
    attn_scores = torch.matmul(q_chunk, key_layer.transpose(-1, -2)) * scale
    attn_probs = torch.softmax(attn_scores, dim=-1)
    ctx_chunk = torch.matmul(attn_probs, value_layer)
    context_chunks.append(ctx_chunk)
context_layer = torch.cat(context_chunks, dim=2)
```
* **Memory Reduction:** Peak temporary allocation drops from **1.36 GB** to **131 MB** (a **10.4x** decrease in activation memory).
* **Speedup:** DINOv2 went from **150.3 seconds on CPU** down to **30.2 seconds on GPU**.

### Innovation B: Zero-Copy Flow Matching Euler Step

#### The Bottleneck:
The Euler scheduler step was originally invoked via diffusers:
```python
outputs = pipe.scheduler.step(noise_pred.cpu().float(), t, latents.cpu().float())
latents = outputs.prev_sample.to(d, dtype=torch.float16)
```
In each diffusion step, transferring 560M tensor activations across the PCIe bus to host CPU RAM and converting between FP16 and FP32 creates substantial synchronization stalls.

#### The Solution:
In Consistency Flow Matching, the Euler integration step is strictly algebraic:
$$x_{t+\Delta t} = x_t + (\sigma_{i+1} - \sigma_i) \cdot v_\theta(x_t, t)$$
We compute this directly on the DirectML device in half-precision (FP16):
```python
dt = float(sigmas_tensor[i + 1] - sigmas_tensor[i])
latents = latents + dt * noise_pred
```
* **Result:** Zero CPU-GPU roundtrips during diffusion, accelerating 5 steps from ~137s down to **~112s**, and 4 steps down to **~89s**.

---

### Innovation C: VAE KV-Cache & 32k Query Batching

#### The Bottleneck:
The VAE's spatial cross-attention decoder (`geo_decoder`) evaluates an octree grid ($129^3 \approx 2,146,689$ 3D points) against the $3,072$ latents generated by the DiT.
Running this in naive chunks of 10,000 queries required 214 kernel dispatches and re-computed the Latent Key/Value projections on every iteration.

#### The Solution:
1. **Latent KV-Caching:** The 3,072 latent vectors are static for a given mesh. By setting `kv_cache = True`, $K$ and $V$ are projected once and kept resident in VRAM.
2. **32,768 Query Batching:** DirectML command queues suffer from per-call dispatch latency. Increasing the chunk size from 10,000 to $32,768$ saturated the compute units of the RX 6600.
* **Speedup:** Volume decoding dropped from **280.3 seconds (CPU)** to **25.1 seconds (GPU)**—an **11.2x** boost.
